Running Dolt in production requires more than the code in dolt.py. The server needs a systemd user service (dolt-bon.service), loginctl linger for headless machines, and a non-root database user scoped to the bon database only. Dolt 1.83.6 removed --user/--password flags from sql-server — the server auto-creates root@localhost on first start, then users must be managed via SQL (CREATE USER, GRANT, DROP USER). The dolt sql local CLI bypasses server auth entirely by running in-process against the data directory, which is both a useful escape hatch and a security consideration. For multi-machine access, the server must bind to 0.0.0.0 or a Tailscale IP (not 127.0.0.1), and the database user needs a wildcard host grant (bon@'%'). Each client machine needs ~/.config/bon/dolt.toml pointing to the server's Tailscale IP. The pymysql dependency must be included in all install paths: uv tool install with [dolt] extras, setup.sh, update-all.sh, and the ensure-bon.sh advisory hint.
