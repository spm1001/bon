The `--how` field was added to bon briefs as an optional fourth field alongside the required why/what/done. The design choice to make it a self-contained string field (not a linked document reference) was deliberate — bon items should replace plan files entirely, not reference external documents. The plan-to-bon transmutation pattern maps directly: why=motivation, how=approach, what=steps, done=criteria. A `_normalize_brief()` helper in display.py ensures JSON output always includes `how: null` for items without it, without polluting stored JSONL. The `OPTIONAL_BRIEF_FIELDS` dict is the single point where optional-vs-required is declared — when `how` becomes mandatory, remove it from that dict and add it to the validation list. The /close skill's `find | head -1` pattern for locating scripts is a systemic bug — it picks whichever cached version comes first in filesystem order, not the latest. Fix is `ls -td` (sort by modification time). Any script-finding pattern in skills should use this approach.
