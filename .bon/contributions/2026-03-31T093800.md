The instruction shard pattern separates always-on behavioral rules from skill context. Shards in ~/.claude/rules/ carry only gates and overrides (e.g. "use bon not TodoWrite", "passe fetch not WebFetch"). Full instructions live in SKILL.md and load when the skill is invoked — no duplication needed. Each plugin's SessionStart hook symlinks its shard using BASH_SOURCE-relative resolution, so version updates auto-propagate. Rules files support path-scoped activation via YAML frontmatter (`paths:` field with glob patterns) for file-type-specific rules, but batterie shards are unconditional since they're behavioral overrides. The @context/ include mechanism and rules/ auto-load are complementary: @context is hand-curated composition controlled by CLAUDE.md, rules/ is plugin-managed auto-load controlled by directory contents.
