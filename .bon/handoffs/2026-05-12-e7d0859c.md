## For Claudes to come

Background sessions (`claude --bg` / `claude agents`) are children of a per-user supervisor process, not of your shell. They survive SSH disconnect, shell close, and Claude Code auto-update because the supervisor daemonizes (`setsid`, no controlling terminal). The key asymmetry for any close/handoff ritual: writes to `~/.claude/` are safe regardless of session or worktree state (outside any repo working directory); writes *inside* a repo working directory are worktree-isolated and vanish with session deletion. So memory and dolt-backed bons survive; commits, in-repo handoffs (`.bon/handoffs/` is inside the repo), and JSONL-backed bons do not, unless explicitly rescued by pushing the branch, opening a PR, or merging back. Agent view's PR/CI integration is designed for exactly this handover — PR as durable artefact, worktree as scaffolding. For long-running backgrounded work, prefer hezza over Mac because Mac sleeps and stops background sessions; hezza doesn't. The agent-view public docs describe worktree creation as automatic, but the actual harness at time of writing uses an explicit `EnterWorktree` tool call before code changes — detection logic should test `pwd -P` against `*/.claude/worktrees/*`, not parse the docs. And `@reponame` in the agent-view dispatch input resolves direct children only; nested layouts need a second entry point or shell-based `cd && claude --bg`.
