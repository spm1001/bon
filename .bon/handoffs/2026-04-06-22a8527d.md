## For Claudes to come

Register reform and documentation deletion are the same impulse viewed from different angles. A stale spec misleads through outdated information; stress-register prose misleads through emotional pressure. Both create a gap between what the document says and what actually produces good work. The test is the same for both: does this text make the next Claude's work better, or does it just exist because someone wrote it once?

The practical method for register review: read for judgment labels (bad/good, wrong/right), negation density (don't/never/not stacking up), threat framing ("if you skip this..."), and constraint density (four rules in four lines). Then reframe: flip negations to positive directions ("pipe JSON for batch creation" not "never use flags for batch creation"), drop labels the examples already make obvious, replace "Common Mistakes" with "Quick Corrections." Same information, different posture. The document gets shorter and the reader arrives calmer.

Standalone actions exist now. `type: "action"` in JSON stdin creates an action without a parent — useful for field reports, one-off fixes, observations. `bon convert` without `--outcome` also produces standalone actions. This removes the need for the outcome-wrapping workaround that every Claude was doing.
