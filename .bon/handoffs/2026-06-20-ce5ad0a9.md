## For Claudes to come

**bon's session rituals must be runtime-agnostic — assume NO harness autoload.** Handoff / understanding.md / room context reaches a session only if the ritual reads it *explicitly*. Harness help spans a wide range and none of it is dependable: Claude Code does the full filesystem walk (ancestor CLAUDE.md at launch, subtree on-demand, `@import` at launch) — but for CLAUDE.md ONLY, never understanding.md or handoffs; Cowork loads ONLY the mounted folder's root CLAUDE.md (no subtree, no `@import`) and its bash tool is a separate sandbox with no bon CLI (bon there is skills + hooks + direct file reads); Cornichon is whatever we author. The only common denominator is "read it yourself." That is why the legible-substrate design (gopewu) is harness-*independent*: walile generates a rooms index, camoru's skill *reads* it (plus the room's CLAUDE.md / understanding.md / handoffs) explicitly — the `@import` auto-load is a CC-only optimization, redundant with the read-in, so it was deliberately dropped, not built.

Two corollaries worth keeping. (1) **Search legibility:** a dotfolder (`.bon/`) is invisible to ripgrep (it skips hidden dirs by default); moving prose to a visible `handoffs/` makes it greppable — that is the legibility *goal*, not noise. Only `.rgignore` bulky raw-transcript dirs, never curated handoffs (notes proves this — its `.rgignore` lists `raw/`, not `handoffs/`). (2) **The mechanism split** that settled the design: zopopu = the path *resolver* (deterministic, runtime-agnostic, `lib-handoff.sh`, shared by reader+writer so they can't drift); camoru = the *judgment* layer (which room did I work in? read it in). Handoff placement is WORK-based — the primary room worked, which the LLM knows at close — not a cwd/launch heuristic (the notes visiting-protocol's rule 4).
