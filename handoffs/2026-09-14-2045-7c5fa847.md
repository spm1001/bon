**The mechanism.** `cmd_new` computed unknown keys as `(set(data) | set(brief_data)) - NEW_TOP_KEYS - EDIT_BRIEF_KEYS`. The union means any key valid at the top level is also "valid" inside `brief`, but only the top level is ever read for it. So `{"brief": {..., "waiting_for": [...]}}` passed the check and the blocker was dropped — rc 0, "Created action", `waiting_for: None`. Reproduced on a scratch board before touching code. The same union sat in `edit_args_from_stdin` (`EDIT_TOP_KEYS`): `{"how": "h", "brief": {"title": "x"}}` applied the how, dropped the title, printed "Updated".

**The choice: accept, not refuse** — for `waiting_for` only. The card preferred accepting, and the code already carried the pattern to mirror: brief fields may be flat or nested with an error if both. `waiting_for` now works flat or under `brief`, errors "given both flat and inside 'brief'" when doubled, and is popped out of `brief_data` so it never lands in the stored brief. The other top-level keys (`title`, `type`, `parent`, `outcome`, `area`) are refused inside `brief` with the existing "Unknown field(s)" error. Reasoning: those are item structure, not item content — a nested `title` is always a mistake, and the error costs one retry where the silent drop cost three items. `area` was the borderline case (a tag, like waiting_for); refused for now, see Uncertain.

**Tests, red first.** Four cases written before the fix, all four failed on current code (the edit one showed rc 0 "Updated: bon-aaa" with the smuggled title), all pass after. `tests/test_new.py::TestNewJsonKeyContract` gained `test_waiting_for_nested_under_brief_is_honoured`, `test_waiting_for_flat_and_nested_conflict_errors`, `test_top_level_key_nested_under_brief_errors`; `tests/test_edit.py::TestEditJsonStdinGuards` gained `test_top_level_key_nested_under_brief_is_refused`. **When a validator checks two namespaces, check them separately.** A union of key sets says "this key is valid somewhere", which is not "this key is valid here", and the drop that follows is silent because the reader only ever looks in one place. The tell is a whitelist built by set arithmetic over more than one dict.
