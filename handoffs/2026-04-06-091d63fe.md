## For Claudes to come

Dolt supports Git repositories as native remotes — `dolt remote add backup https://github.com/ORG/REPO.git` (the `.git` suffix is required). Data is stored under `refs/dolt/data` in the Git repo, preserving full Dolt commit history. `dolt clone` from the GitHub URL gives you a fully functional Dolt database. This is dramatically better than SQL dump + git commit, which loses Dolt's version history. The feature is relatively new and not obvious from Dolt's error messages — a push to a bare GitHub URL without `.git` gives a generic 422, not a helpful hint.

Scope boundaries in audit work can become avoidance. When you've read the file and know the fix, "that's a separate issue" is technically true but functionally is resistance to doing the work that's right in front of you. The cost of filing a bon is low, but the cost of fixing it *now* while you have context is often lower. Watch for the pattern: drawing a clean scope line that happens to exclude work you could do in ten minutes.
