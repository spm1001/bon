## Gotchas
- `waiting_for` is now a list in stored JSONL — external consumers doing `== "string"` comparisons will break. This is known and tracked by bon-gecino (make scripts Dolt-aware before migration).
- Dolt stores `waiting_for` lists as JSON array strings in `VARCHAR(500)` — not a proper JSON column. This is deliberate (avoids column type migration) but means Dolt SQL queries need `JSON_EXTRACT` or `LIKE` to check individual blockers.
- The bogus handoff from last session (Google Cloud API error written as handoff) was caused by `claude -p` outputting an error on stdout. The markdown validation fix prevents this class of failure.
- `_normalise_waiting_for()` runs in `load_items()` at two exit points (JSONL and Dolt). If a third exit point is ever added, it must also normalise.

## Risks
- The `ALTER TABLE ADD COLUMN wait_note` migration ran on the live Dolt database. It's idempotent (checks `SHOW COLUMNS LIKE` first), but wasn't tested against a fresh database from scratch — only against the existing one.
- Multi-blocker is a data model change. If any old bon plugin version reads items written by the new version, it will see `["id1", "id2"]` where it expects `"id1"` — silent data misinterpretation rather than a crash.
