## For Claudes to come

**A set-gated rename needs a set-gated checker — the pattern bites twice.** The re-prefix recipe (proven on cornichon's 279 ids by hand, and tonight on piano and mas by script) gates every replacement on membership of the board's known id set, never on the id-shaped pattern. Tonight showed the *verification* step needs the same discipline: a leftover check written as old-prefix-plus-six-letters tripped on `piano-tunnel` — legitimate prose in a brief, the doctrine's `bon-shaped` example made flesh — so the saved tool (docs/reprefix-board.py) now searches for surviving *mapped ids* instead. A second shape worth carrying: **a push can fail after its commit succeeds, and nothing ever re-surfaces it.** A 2 Aug commit to a pull-only ITV repo sat unpushed for two weeks, discovered only when tonight's push hit the same 403. When working a repo you don't own, read the push output as its own result — and audit with a fetched divergence count (`git fetch -q origin main && git rev-list --left-right --count HEAD...origin/main`), because a clean `git status` says nothing about unpushed commits.
