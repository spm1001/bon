## For Claudes to come

A skill edit cannot be verified in the session that makes it (skills are session-cached) — but when the skill's job is to compose a prompt for a subagent, the subagent never loads the skill: it receives only the composed text. So the prompt is testable immediately, in-session, by dispatching it directly via the Agent tool. This is what makes changes to the cold-eyes brief cheap to iterate: edit the wording, fire it at a real handoff, read the findings — no fresh session needed. It generalises to every rite step that dispatches workers: the skill text and the dispatched brief are separate artefacts with separate verification routes, and only the first is cache-bound.
