## For Claudes to come

**The repos mapping table (Dolt) and why it's shaped this way.** The shared Dolt database now carries `repos` (prefix PK → repo_name, origin_url, updated_at), the thing that lets estate-wide consumers label prefixes without a local clone. Registration is deliberately parasitic: `_register_repo` runs inside the existing save/archive write transaction so it rides the same Dolt commit — zero extra commits — and it SELECT-compares before writing so an unchanged identity adds nothing (the integration test plants a sentinel and asserts it survives a save; comparing timestamps would false-pass within a second). `bon init --backend dolt` soft-fails registration when the server is unreachable (offline init stays valid; the board self-registers on first write). Unmapped prefixes must stay fail-visible ("xyz (unmapped)") — a guessed label would defeat the whole design.

**Hybrid survey semantics worth not re-deriving.** `not_cloned_here` means "no clone under the scan roots", not "not on this machine" — `~/.dotfiles` is the standing exception (Dolt-backed, outside roots, actually local). A Dolt outage degrades the survey to JSONL-boards-only — local Dolt boards ALSO read empty because `bon list` needs the same server — so the fallback names itself loudly rather than posing as the estate. First real run: 491 open / 27 boards, of which 169 items were invisible to the old filesystem-only survey (plongeur 52, claude-in-office 34, aboyeur 26, tafelmusik 26, …).

**Scratch-Dolt-server pattern for integration tests.** Never point BON_DOLT_TEST=1 at production — test commits pollute the shared dolt_log and test_migrate's live test uses prefix "bon" (it would collide-and-refuse on production, and leak rows on anything else). Recipe: `dolt init` in a temp dir (needs `dolt config --global user.name/email` set or init fails "empty ident"), `dolt sql-server --port 3307`, then BON_DOLT_* env vars — env overrides beat dolt.toml. Gotcha bought tonight: any test that triggers a Dolt write now also creates a `repos` row, so integration fixtures must clean `repos` alongside items/archive (all three cleanup sites do, as of 1.5.0).
